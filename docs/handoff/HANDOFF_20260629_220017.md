## 5. What this session changed (with the why)

### 5a. Git-provider integration fixes (`internal/gitproviders`, committed `23f9650`)
- **Auth header now scoped to the repo's exact origin.** `httpsTokenAuth` used a hardcoded
  `[http "https://<host>/"]` gitconfig section. Git only attaches an `http.<url>` extraheader when
  scheme+host+port match — so for a **self-hosted Gitea/GitLab over plain http or a non-default port**
  the token was silently dropped and "Test" failed against a valid repo. Fix: `Provider.BuildAuth(repo
  string)` derives `authScope(repo, host)` = `scheme://host[:port]/` from the target repo; threaded
  through `Verify` (the Test button), the bridge clone path (`resolveGitAuth` → `cfg.Project.GitRepo`),
  and `scan_handlers`. Falls back to `https://host/` when repo unknown. Test:
  `TestTokenAuthScopesToRepoOrigin`.
- **Service preset persisted in `meta`.** The Add/Edit provider modal has GitHub/GitLab/Bitbucket/
  Gitea/Other presets (all stored as `kind=token`; the token engine is provider-agnostic). The chosen
  service is now saved to the provider's `meta` json (`{"service":"…"}`) so **Edit reopens the right
  tab** (host string alone can't identify a self-hosted service), and preset buttons no longer **blank**
  a typed host/username (they only overwrite when the preset has a non-empty default). `Update()` gained
  a `meta` param; `gitProviderBody` gained `service`.
- Backlog: real OAuth "Connect GitLab/Bitbucket/Gitea" (Phase 2; tokens cover plain cloning today).

### 5b. UI-managed Traefik plugins — Phase 3.1 (`internal/traefikcfg`, `internal/geoipdb`, committed `23f9650`)
- Rigger now **owns the full Traefik static config** (`traefikcfg.Generate` → `traefik.yml` on the
  shared `rigger-traefik-config` volume, mounted at Traefik `/etc/traefik`). The compose `command:` was
  removed (static-config sources are mutually exclusive); `rigger-traefik` `depends_on: rigger
  service_healthy`; rigger gained `/healthz`. Toggling WAF/GeoIP in **Proxy Service → Plugins** rewrites
  the file + restarts Traefik (`acme.New(nil).RestartProxy()`). GeoIP DB download = `internal/geoipdb`
  (IP2Location LITE, `POST /api/settings/proxy/geoip`). **Live-verified: Coraza WAF + geoblock GeoIP.**

### 5c. Proxy Service Routes-section UI (committed `5e7214a`)
- The route list now sits in a card with its own **"Routes"** header + a section-level **Add route**
  button (matching the Access lists / Plugins cards); page-header Add-route button removed; empty state
  folded into the card.

### 5d. Souin cache plugin HARD-DISABLED (committed `b27a195`) — **the important one**
- **Souin (the cache plugin) panics under Traefik's Yaegi interpreter at load.** A failing plugin
  poisons **router building**, so with Souin declared, Traefik stayed "up" but **dropped every
  Docker-provider router to 404** — all hosted apps went down (a live Gitea answered on its published
  host port but 404'd on its domain). There is **no Yaegi-compatible cache plugin** to swap in.
- **Fix:** `const traefikcfg.CacheSupported = false` is the single source of truth, AND-ed into
  `FromSettings.Cache`, `Generate`'s souin block, `proxy_handlers.renderProxy`, and the bridge cache
  flag — so souin is never emitted (static) and no `proxy-cache@file` middleware is referenced
  (dynamic). Plugins UI shows Cache as **unavailable** with CDN/sidecar guidance. **To re-enable later:
  flip that one const to `true`** (only once a Yaegi-compatible cache build exists).
- Caching alternatives (none built): a **CDN in front (Cloudflare)** or a **cache sidecar (Varnish /
  Nginx `proxy_cache`)**.

## 7. Critical gotchas (inline — the next account won't have these in memory)

1. **Souin/Yaegi cache (see §5d):** never re-enable Cache without a Yaegi-compatible build; one bad
   plugin 404s *all* hosted apps while Traefik still shows "up."
2. **Gitea bare `HTTP_PORT` collision:** Rigger's generated `.env` carries an env-level
   `HTTP_PORT=<env.http_port>` and `env_file: .env` injects it into every container. Gitea reads a bare
   `HTTP_PORT` → listens on the wrong port → unhealthy + unreachable (removing the healthcheck is a red
   herring). Fix per-app: pin the app's own port var (`GITEA__server__HTTP_PORT`). Underlying wart:
   env-level `HTTP_PORT`/`HTTPS_PORT`/`MAIL_PORT` shouldn't leak into app containers (spawned task
   `task_8e1a4fd6`).
3. **`web_routed` flag:** for image-stack/compose-import services, **`web_routed: true`** on a service
   is what makes composegen emit Traefik labels + attach `traefik_net`. Choosing "Traefik routing" at
   the env level does NOT set it on a multi-service stack — that's a wizard bug (`task_c3608ae5`).
4. **Postgres password drift:** Postgres sets `POSTGRES_PASSWORD` only on **first** data-volume init;
   later `.env` regeneration diverges from the stored password → app DB auth fails. Reconcile with
   `ALTER ROLE` or wipe the (empty) volume. A loopback `trust` rule can make a same-container psql test
   a false positive — test over the network (scram) to validate a password.
5. **Traefik static config is mutually exclusive** (file vs CLI vs env). Rigger owns the file; never
   add a compose `command:` back to `rigger-traefik`.
6. **`workspaces/` is gitignored** — live project edits aren't committed; apply them on disk + redeploy.
7. **Cross-provider Traefik refs:** hosted app routers (Docker provider) reference `rigger-loading@file`
   (file provider). If a router references a missing/failed middleware, Traefik **drops the whole
   router → 404**. (This is also how souin took everything down.)
8. **Push-to-develop is harness-gated** (see §3).
